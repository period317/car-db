# 인수인계 — 웹 접속이 되는 AI가 이 DB 작업을 이어서 하는 법

이 문서를 **가장 먼저** 읽으세요. 이 폴더는 사용자(허호필)와 Claude가 함께 만든 국내 신차 **월별 혜택 DB**입니다.
회사 PC의 AI는 외부 웹 검색이 막혀 있어 이 저장소의 파일만 읽습니다. 웹 접속이 되는 AI(또는 사람)가 이 문서대로 이어서 수집하면 됩니다.

## 1. 이 DB의 목적 (사용자가 직접 정한 원칙)
1. **목적은 월별 혜택**이다: 할인, 이벤트, 금융 프로모션, 시승 혜택(추첨·경품). 차량 가격은 참고 정보일 뿐 수집 목표가 아니다.
2. **대표값을 고르지 않는다.** 중간값·최저가·최다판매 트림만 넣지 말고 페이지에 있는 정보를 **전부** 넣는다. 데이터가 늘어나도 괜찮다.
3. **어떤 모델이 지금 혜택 중인지**가 핵심이다. 모델별 가격은 내부 DB에 따로 있다고 사용자가 말했다.
4. 혜택 한 건은 **기준년월 / 모델·세부모델 / 이벤트명 / 할인 여부와 조건 / 시승 혜택(뭘 주는지) / 기타 이벤트 / 링크**로 정리한다.
5. **차량 모델명과 이벤트명을 섞지 않는다.** 할인 금액은 **별도 숫자 컬럼**이다.
6. **틀리면 안 된다.** 읽은 원문을 저장하고 자동 대조한다(아래 4). 대조 안 된 값은 "원문 대조 안 됨"으로 표시한다.
7. 다른 AI가 파일만 읽고도 **같은 표를 똑같이 만들 수 있어야** 한다. 그래서 AI용 파일에 표 작성 규칙과 예시를 넣었다.

| 경로 | 설명 |

## 4. 이어서 작업하는 순서 (웹 접속 가능한 AI용)
1. `docs/SITE_GUIDE.md`의 "확인 현황" 표에서 **미확인** 브랜드를 고른다(우선순위는 판매량 순: 기아·현대·제네시스·르노·KGM·쉐보레 / 벤츠·BMW·테슬라·렉서스·아우디·볼보·미니·토요타·폭스바겐·포르쉐).
2. 브랜드마다 **구매혜택 페이지와 이벤트 목록 페이지를 둘 다** 연다(르노에서 이벤트 목록을 안 봐서 시승 이벤트를 놓친 적이 있다).
3. 읽은 본문을 `data/evidence/<brand>/<오늘>_<slug>.txt` 로 저장한다(형식은 `docs/COLLECTION_GUIDE.md` 3절).
4. `data/offers/<brand>_*.json` 에 옮긴다. 이벤트는 `events_extra`, 모델별 혜택은 기존 구조를 따른다. **증거에 있는 내용만** 쓴다.
5. 시승 이벤트면 `data/testdrive/index.json` 의 해당 브랜드(`has_event`, `event_*`)도 고친다.
6. `powershell -ExecutionPolicy Bypass -File scripts\update_all.ps1` 실행. 품질 점검 ERROR가 있으면 게시되지 않으니 `docs/QUALITY_REPORT.md`, `docs/VERIFY_CHECKLIST.md` 를 보고 고친다.
7. 끝나면 `docs/SITE_GUIDE.md` 의 확인 현황과 `docs/LESSONS.md` 를 갱신한다(새로 알게 된 사이트 구조·함정).

Python은 항상 `python -I`(격리 모드)로 실행한다. 한글이 든 PowerShell 스크립트는 UTF-8 BOM으로 저장한다.

## 4.5 사용자 지시 (2026-11-06)
- **대상 월(지금은 11월)과 기간이 겹치지 않는 혜택은 뺀다.** `benefits_excluded.*` 에 보관(BMW 10월 금융 프로모션 15건, 렉서스 가을 시승회 1건이 제외됨).
- **공식 홈페이지에서 직접 읽어 확인되지 않은 혜택은 정리하지 않는다.** 검색 결과 요약으로만 본 것은 넣지 않는다.
- **범위는 '11월 구매 혜택(할인·시승·금융)'.** 서비스·멤버십·제휴 이벤트는 정리하지 않는다. 이미 수집한 것은 `data/scope_exclude.json` 규칙으로 제외(25건 규칙 → `benefits_excluded.*` 에 이유와 함께 보관). 범위 밖 항목을 새로 만나면 이 파일에 규칙을 추가한다.
